# 本机运行监控

在控制端启动，使用与提交任务相同的私有 profile：

```bash
python3 tools/eda.py dashboard --profile profiles/machine.local.json
```

在同一台电脑的浏览器中打开 `http://localhost:8765/`。支持已有的 `local`、`ssh`、`windows_ssh` 传输方式。WSL 调用 Windows OpenSSH 时，继续沿用现有可用的 WSL 互通环境。

可选参数：

```bash
python3 tools/eda.py dashboard --profile profiles/machine.local.json --port 8765 --refresh 5 --request-timeout 15
```

- `--port`：本机监听端口，默认 8765。
- `--refresh`：刷新/缓存间隔，默认 5 秒，范围 2–60 秒。
- `--request-timeout`：单次执行端读取超时，默认 15 秒，范围 2–60 秒；只作用于监控，不更改 profile 文件或工具超时。

启动服务后，后续提交到同一运行根目录的任务会自动出现。服务默认在当前终端运行，Ctrl+C 停止服务；停止服务和关闭网页均不停止 EDA worker。该页面不提供提交、取消或恢复按钮，这些操作继续使用执行器 CLI。

## 显示内容

| 区域 | 数据含义 |
|---|---|
| 任务列表 | 当前运行根目录最近更新的至多 200 条记录；执行中和排队任务优先，可按结果筛选 |
| 阶段进度 | 实际阶段执行与验收状态；显示沿用哪个 attempt 的 checkpoint，未执行的下游保持未执行 |
| 工程流程图 | 按 flow 声明的执行顺序连接阶段；验收失败后的边标为阻断，阶段未拆分时不推断内部 placement/CTS 子步骤 |
| Error / Warning | 所选流程路径上主日志的已识别消息次数，包含继承阶段，每阶段只计一次；Error 包含 Fatal，恢复探测日志单列 |
| 消息分布图 | 横向对比每阶段 Error、Warning 次数；未生成日志保持未知，尚未扫描完整的计数显示为下界 |
| 问题明细 | 按阶段、级别、消息代码聚合；可搜索内容，查看重复次数，并点击日志行号定位上下文 |
| 物理验收 | DRC / open nets 从已有验收报告的观测记录读取，RC 使用已有验收结果；这些不是日志中的 Error 次数 |
| 耗时 | 当前 attempt 的开始至结束/最近采样时间；排队中显示提交后的等待时间，不伪造预计完成时间 |
| CPU | 所属工具进程组 CPU 时间的采样差值，100% 对应一个逻辑核；首个样本、进程组切换或没有进程时显示未知 |
| 内存 | 活跃进程组当前 RSS；结束后显示该 attempt 已完成阶段记录中的峰值。共享页可能重复计数，不等同于整机内存或 cgroup 统计 |
| 曲线 | 当前监控服务记忆的最近 120 次采样；服务重启后清空，不作为完整资源历史 |
| 日志 | 所选 attempt 的工具、恢复探测或 worker 日志尾部，每次最多 64 KiB；可选择日志、暂停刷新、控制自动滚动、复制文本 |
| 验收结论 | 执行失败、证据不足和验收未通过分别显示；阶段完成不代表 QoR 可比或 signoff |

CPU 累计值只覆盖采样时仍存在的进程；短进程在两次采样间退出可能漏计，不能据此进行精确 CPU 计费。服务刚启动时也无法补回之前的曲线。

## 读取范围和故障处理

每次刷新读取执行器状态、阶段定义、日志尾部或定位窗口、消息统计所需的新增日志片段，以及 `/proc` 采样，不重新检查整个工程或 PDK。响应不包含 profile、环境变量、输入指纹树或工具启动命令。HTTP 层合并重复读取并缓存，避免多个浏览器标签页连续发起相同 SSH 请求。

### 计数口径

- 统计从阶段日志开头开始，覆盖已输出的完整行；后续按游标只读新增内容，不从最后 64 KiB 推算全量计数。
- 识别行首的 `Error:`、`Fatal:`、`Warning:`、`Information:` 等消息，兼容 VCS `Error-[CODE]`、UVM 消息和 Python traceback 起始行。命令回显中的 `echo "Warning: ..."`、诊断汇总中的数量、`UVM_ERROR : 0` 不重复计入。
- 同一代码的消息按出现次数累计，归入一组；无代码时按消息文本归组。每组保留最多 3 处原文位置。计数是已打印的消息次数，不是去重后的根因数；工具抑制而未打印的消息无法补算，未知格式也不能据此判定没有错误。
- 主流程与 checkpoint 重新打开验证分别统计，默认图表和总数只看主流程。恢复出来的阶段引用原 attempt 的日志，不冒充在新 attempt 重新执行。
- 报告中的 DRC/open 数量不加到 Error 计数中；例如“没有识别到 Error 行”仍可能伴随物理验收失败。相同指标若多个报告给出不同值，会保留各条观测，不随意相加或选一个值。
- 对历史大日志分块补齐：每次请求最多传回 4 MiB 统计数据，单文件最多 2 MiB；未读完时显示“统计中”和 `≥` 下界。活跃日志的末尾半行待续写完成后再计入，结束日志可处理无换行的最后一行。
- 日志截断、轮转或游标附近内容被改写会触发重新统计。缓存只驻留控制端内存，服务重启后重新扫描，不改写原日志或运行状态。每份日志最多保留 200 个细分组，超出部分按级别归入 `OTHER`，次数仍累计；超长单行保留前 64 KiB，消息样例最多 1200 字符。

点击消息原文时读取不超过 64 KiB 的定位窗口，高亮对应行。日志的 attempt 可以独立切换，因此查看继承阶段的历史消息时仍保留当前流程图；“回到最新”恢复尾部查看。

SSH 断开或读取超时后，页面明确显示连接失败和上次成功读取时间，已有数据显示为过期数据。不会把连接问题写成工具失败，也不修改任务状态。恢复连接后自动更新。该页面只跟踪通过本执行器创建的任务，不会自动接管其他终端手工启动的 EDA 进程。

## 本地数据边界

服务仅绑定 loopback，校验请求 Host/Origin，不提供跨域访问或任意文件下载。所有前端资源随仓库提供，无外部 CDN、字体或统计请求。监控页面只在本机提供服务，不部署到外部网站。

日志本身可能包含本机路径和项目数据，只在本地页面显示。真实 profile、截图、日志和采样结果应放在忽略目录；同步 GitHub 时只提交通用代码、说明和人工测试数据。其他设备访问不在默认配置范围内，需要另行设置受控访问方式。

## 验证

公共测试检查只读行为、日志大小限制、profile 数据隔离、实际模拟进程的 CPU/RSS 采样、历史 attempt 选择、断线后保留旧数据、重复请求缓存，以及拒绝写请求、任意文件路径和跨站请求。消息统计另测试重复刷新不重计、汇总/回显排除、跨块 UTF-8 和半行、截断/轮转、大文件限量补齐、分类上限和继承日志定位。浏览器验收覆盖流程连线、分布图、筛选下钻、原文高亮以及桌面/窄屏布局；真实环境截图不进入仓库。
